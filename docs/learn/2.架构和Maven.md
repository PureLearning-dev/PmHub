在一个 Maven 项目中可以有许多的 Maven Module。这种结构叫：Maven 多模块项目（Multi-Module Maven Project）。

Maven 模块具有独立 pom.xml 的构建单元，通常一个 Maven 模块会生成一个构建产物 —— xxx.jar 。

如果多个 Maven 模块中只有一个模块中存在启动类，则最终也只会产生一个 jar 文件，此时仍然是一个单体应用，模块之间必然是呈线性依赖的，
只不过是将项目拆分得更加清晰，便于理解和构造。

如果每个业务模块都有自己的启动类，则会构建得到多个 jar 文件，此时，多个 jar 文件可以独立部署、启动、运行等操作，不同服务之间交互需要进行通行才行。

SOA（Service-Oriented Architecture，面向服务架构）的核心是： 按业务能力把系统拆成若干相对独立的“服务”，服务之间通过明确的接口通信。

例如项目管理平台可以拆成：

- 用户服务：登录、注册、权限
- 项目服务：项目创建、成员管理
- 任务服务：任务分配、状态流转
- 通知服务：邮件、站内消息
  
这些服务通常有清晰的边界，可能分别运行和部署。

SOA 和微服务的思想相近，但传统 SOA 通常服务粒度更大，也更强调企业系统集成；微服务更强调独立部署、轻量通信和团队自治。

Maven 是什么？如何理解呢？其诞生是因为“约定大于配置”，并在此基础上添加了更多的功能。

Maven 根据 pom.xml 描述，把源代码、依赖和插件按照生命周期构建成 JAR/WAR；多模块 Maven 则由根 POM 统一聚合、配置并按依赖顺序构建多个子模块。

Maven 更像一个调度器，真正执行的工具其实是插件！

Maven 读取 pom.xml 中的内容，按照标准生命周期，在约定目录中寻找文件，然后调用对应插件完成构建。

甚至 Maven 中的约定是可以修改的！下面的代码可以修改源代码和测试代码的默认文件夹。

```xml
<build>
    <sourceDirectory>source</sourceDirectory>
    <testSourceDirectory>tests</testSourceDirectory>
</build>
```
